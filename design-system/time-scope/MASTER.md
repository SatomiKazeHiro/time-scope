# Time Scope 设计系统

**基调：仪表盘（instrument panel）**

一整条依据：这是个**常驻后台**的应用。它一整天开着，用户大部分时间是余光扫一眼——
"上午在干什么""现在在专注吗"——而不是坐下来仔细读。仪表盘的视觉语言正好对应这种用法：
密集、克制、数字优先、颜色只用来回答一个问题。

不选的方向，以及原因：

| 不选 | 原因 |
|---|---|
| 玻璃拟态 | 时间线是密集色块，背后做模糊既掉可读性又掉性能。`backdrop-filter` 在常驻应用里是持续的 GPU 开销 |
| 落地页式排版 | 这不是营销页。首屏不需要 hero、数字指标卡、三段式卖点 |
| 只做深色 | 深色确实更适合托盘常驻的余光扫视，所以它是默认值。但只给一套等于替用户做了决定 —— 白天的办公室、投屏演示都要浅色。**深浅两套都是完整选定的色板，不是互为反色**，见 §2 |
| 等宽字做标题 | 界面是中文，等宽字族没有中文字形，中文会回退到系统字体，字面直接碎掉。等宽只用在时间码上 |

## 1. 两条不可破坏的规则

### 1.1 界面层不借用数据色相

蓝、橙、青三个色相**全部**让给类别。选中、聚焦、主按钮一律用**明度**表达
（`--color-neutral-solid` 的亮色块 / 亮色描边环）。

原因：一旦按钮用了蓝色，用户在时间线上看到蓝色就会犹豫"这是 work 类别，还是这里被选中了"。
数据可视化的规矩是「文字穿文字色，不穿系列色」；这里把它扩大成「界面 chrome 不穿数据色相」。

状态色（good / warning / critical）是**保留语义**，永远不当作第 4 个类别色。
它们按约定必须配图标或文字，不靠颜色单独表意。

### 1.2 idle 与 unknown 不是类别，是"无"

它们走中性灰，且刻意压到 3:1 对比度以下（1.89:1 / 1.35:1），让长段空白退到背景后面。

原因的语义性大于技术性：一天里 8 小时空闲**就该看起来是空的**。
旧配色里 `idle: #b0b6bd` 在深色底上偏亮，把睡觉画得比工作还抢眼。

## 2. 类别色板

色值真相在 **`src/styles/theme.css`**（`--color-cat-*`）。本文档是解释，不是副本。

**深浅两套各自独立选步进，不是互为反色。** 关键在"主/次"的方向会跟着底色翻转：

- 深色底上，更显眼 = **更亮** → 主类别取亮档
- 浅色底上，更显眼 = **更深** → 主类别取暗档

浅色底对白底的对比度余量也比深色底紧，次档被 3:1 的标记线卡在很窄的一条带上
（见 §2.4 的取值）。

| 类别 | 中文 | 层级 | 阶 | 深色 | 浅色 | 深底对比 | 浅底对比 |
|---|---|---|---|---|---|---|---|
| work | 工作 | 专注 | 主 | `#3987e5` | `#3082ce` | 4.84:1 | 4.03:1 |
| study | 学习 | 专注 | 次 | `#256abf` | `#3d98ed` | 3.27:1 | 3.04:1 |
| browsing | 浏览 | 消耗 | 主 | `#d95926` | `#c8622f` | 4.54:1 | 4.00:1 |
| entertainment | 娱乐 | 消耗 | 次 | `#b0471c` | `#ea7235` | 3.16:1 | 3.02:1 |
| communication | 沟通 | 社交 | 主 | `#199e70` | `#338f6d` | 5.17:1 | 3.97:1 |
| life | 生活 | 社交 | 次 | `#107a56` | `#3aa57e` | 3.31:1 | 3.06:1 |
| idle | 空闲 | 无活动 | — | `#3f4756` | `#b8bec7` | 1.89:1 | 1.87:1 |
| unknown | 未分类 | 无活动 | — | `#2b313b` | `#d5d9df` | 1.35:1 | 1.42:1 |

两套都经 `verify-palette.mjs` 校验（底色分别是 `#151920` 和 `#ffffff`）：

```
深色  3 色相 all-pairs     PASS   CVD ΔE 9.4 / 常色 ΔE 20.9
浅色  3 色相 all-pairs     PASS   CVD ΔE 8.9 / 常色 ΔE 16.6
两套  层级内明度阶 ordinal  PASS   3/3 单色相、ΔL ≥ 0.06
两套  6 个类别色块对底色     PASS   6/6 ≥ 3:1
两套  段内直标配字           PASS   6/6 ≥ 4.5:1
```

### 2.1 为什么不是八色平铺

时间线是**任意两类都可能相邻**的（work 紧挨 browsing 也可能），
所以校验必须按 all-pairs 走，而不是默认的 adjacent。

暴力枚举 8 个候选色相的全部 56 + 70 + 28 种组合（n=3/4/6）后：

| 类别数 | all-pairs 通过数 | 最优最差一对 CVD ΔE |
|---|---|---|
| 3 | 15 / 56 | 13.2 |
| 4 | 2 / 70（且都落在 6–8 保底带） | 6.9 |
| 5 | **0 / 56** | 6.7 |
| 6 | **0 / 28** | **2.7** |

ΔE 2.7 意味着**在红色盲下两个类别几乎完全同色**。八个类别各占一个色相
在这张时间线上不成立，这不是审美偏好问题，是算术问题。

### 2.2 实际方案：3 色相 + 明度阶

色相只承载三个大层级（专注 / 消耗 / 社交），层级内用明度区分具体类别 ——
这是 ordinal 结构，判据是「单色相、明度单调、相邻 ΔL ≥ 0.06」。

浅色色板不是深色那套反过来的，是按同样判据在 OKLCH 空间重新搜的：
沿同一色相角扫明度，取「对底色 ≥3.4:1 且配深字 ≥4.5:1」的最深一档当主类别，
再取仍满足 ≥3:1 的最浅一档当次类别。第一版搜索允许低饱和度，
结果选出了色相飘移 44° 的土黄色 —— **低饱和度下色相是病态的**，
搜索时必须同时设 chroma 下限（这里用色域内 C 的 0.85 倍）。

### 2.3 无障碍兜底：身份不能只靠颜色

层级内的两个类别靠明度区分，弱视用户**可能**并排混淆。所以身份识别走三条冗余通道，
任何一条单独失效都还能读出来：

1. **常驻图例**（当日汇总面板）—— 每行都有色块**和**中文类名，不是只有色块
2. **段内直标** —— 色块够宽（> 46 viewBox 单位）时直接写类别名
3. **悬停浮层 + 选中读数** —— 点开就给出类别、应用、起止、时长

**两处例外（`src/design/categories.ts` 的 `inlineLabel: false`）**：
`study` 和 `life` 在**两个主题下都**拿不到段内直标。深色底下它们的浅字只有
4.47 / 4.41:1，压在 4.5 线下；调深则对底色的标记对比跌破 3:1，**蓝相在这条窄区间里无解**
（已全扫确认）。

浅色底下这两档其实够（深字 4.5+），但**不能因此只在浅色时打** ——
让界面结构随主题变化（某些主题下多出标签）比"标签一直不打"更难预期。
所以 `inlineLabel` 是结构决策，标签颜色交给 CSS 的 `--on-cat-*` 随主题走，两者分开。

### 2.4 图例色块带描边

图例和详情里的类别色块都加 `inset 0 0 0 1px var(--color-line-strong)`。
`unknown` 压在 `surface-1` 上深色只有 1.35:1、浅色 1.42:1，不描边的话那个 10px 的方块
会**完全看不见**，看起来像渲染坏了 —— 而图例正是无障碍兜底通道，它不能坏。

## 3. 主题机制

三态循环：**跟随系统 → 浅色 → 深色 → 跟随系统**，按钮在页头「采集中」右侧。
选择存 `localStorage` 的 `time-scope.theme`。

**解析完全交给 CSS。** `useTheme`（`src/design/useTheme.ts`）只把选择写成
`<html data-theme="...">`，实际切换靠 `theme.css` 的三条路径：

| 选择 | 谁生效 | 机制 |
|---|---|---|
| `system` | `@media (prefers-color-scheme: light)` + `:root:not([data-theme="dark"])` | 系统变了不用 JS 监听，媒体查询自己跟上 |
| `light` | `:root[data-theme="light"]` | 显式覆盖，压过媒体查询 |
| `dark` | 什么都不匹配，落到 `@theme` 默认值 | |

### 3.1 浅色 token 为什么写了两遍

媒体查询块和 `[data-theme="light"]` 块各有 32 个 token，值必须逐条一致。

本来想用一段内联脚本在 React 挂载前解析主题来消重，但**生产 CSP 是 `script-src 'self'`，
内联脚本会被拦**（见 `src-tauri/tauri.conf.json`）。改 CSP 去迁就一个样式问题不划算，
让 JS 解析则每次启动都有一次主题闪烁。

所以保留重复，改为**机器兜底**：`verify-palette.mjs` 的第 0 项检查会逐条比对两份声明，
多一个、少一个、或值不一致都会直接失败。改色时漏改一份会立刻被抓住。

### 3.2 表面与层级

两个主题都**用明度差表达层级，不用阴影**。阴影只留给浮层。

| token | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--color-surface-0` | `#0c0f14` | `#eef0f3` | 页面底 |
| `--color-surface-1` | `#151920` | `#ffffff` | 面板 / 时间线底（类别色对着它校验） |
| `--color-surface-2` | `#1c222c` | `#f4f5f7` | 悬浮 / 输入框 / 轨道 |
| `--color-surface-3` | `#232a36` | `#ffffff` | 浮层 / 提示条 |

分隔线用半透明对比色（深色下白 8%、浅色下近黑 10%），比实色灰在两个底上都更稳。
`color-scheme` 跟着主题切，日期选择器、滚动条这些原生控件才会跟着变。

**状态色两个主题取值不同**，因为参考色板的固定状态色在白底上不成立：

| token | 深色 | 浅色 | 用途 | 门槛 |
|---|---|---|---|---|
| `--color-state-good` | `#0ca30c` | `#0a8a0a` | 采集中指示 | 3:1（仅图标） |
| `--color-state-warning` | `#fab219` | `#8a5a00` | 「已脱敏」角标 | 4.5:1（**当文字用**） |
| `--color-state-critical` | `#d03b3b` | `#d03b3b` | 错误图标 | 3:1（仅图标） |

`#fab219` 在白底上只有 1.83:1，当文字读不出来，所以浅色主题换成 `#8a5a00`（5.93:1）。
`verify-palette.mjs` 的门槛是**按实际用途**定的，不是所有状态色一刀切 4.5:1 ——
改用途时要同步改那里的门槛，否则检查名不副实。

## 4. 文字

```
正文   system-ui / Segoe UI Variable / 微软雅黑      14px
时间码 Cascadia Mono / Consolas + tabular-nums        11–14px
```

- **不下载 webfont。** 离线桌面应用，且常驻内存预算 < 80MB（STATUS §3）。
  引入 webfont 意味着多一个网络依赖和一份常驻字体内存。
- **`.tnum` 工具类**给所有数字读数（时间码、时长、百分比、置信度）。
  非等宽数字在每秒刷新的读数上会左右抖动。
- 字阶比通用产品小一档：11 / 12 / 13 / 14 / 16 / 20px。仪表盘取向，信息密度优先。
  **11px 只用于刻度和角标，不用于正文。**

## 5. 交互

| 项 | 值 |
|---|---|
| 间距 | 4px 基准 |
| 圆角 | 控件 `3px` / 面板 `6px` / 浮层 `10px`；时间线色块 `1px` |
| 动效 | 只有两档：hover/按下 `120ms`，面板 `180ms`；缓动 `cubic-bezier(0.25,1,0.5,1)` |
| 浮层阴影 | `--shadow-pop`：`0 3px 10px`，深色 34% / 浅色 10% 不透明度。原本 24px 模糊 + 45% 太重，压过了它要提示的内容 |
| 焦点环 | `2px` 亮色（`--color-neutral-solid`）—— **不用浏览器默认蓝环**，蓝是 work 的色相 |
| 减动效 | `prefers-reduced-motion` 下全部归零，见 `theme.css` |

常驻应用会在用户眼前跑一整天，任何无意义的过渡对他都是**持续的**干扰。
所以这里没有入场动画、没有转场、没有骨架屏微光。

## 6. 图标

**lucide**（`lucide-react`），单一图标族，描边统一 2px。不用 emoji 做结构性图标。

| 位置 | 图标 |
|---|---|
| 前一天 / 后一天 | `ChevronLeft` / `ChevronRight` |
| 日期选择 | `CalendarDays` |
| 采集中指示 | `Radio`（配 `state-good`） |
| 主题：跟随系统 / 浅色 / 深色 | `Monitor` / `Sun` / `Moon` |
| 错误 | `CircleAlert`（配 `state-critical`） |
| 详情：时间 / 应用 / 置信度 / 证据 | `Clock` / `AppWindow` / `Gauge` / `Layers` |
| 脱敏标记 | `ShieldCheck`（配 `state-warning`） |

主题按钮的图标表示**当前**状态而不是点击后的结果 —— 三态循环里"下一步"随当前值变，
用固定图标（只显示下一步）反而更难预测。

图标一律 `aria-hidden`，语义由旁边的文字承担。**图标按钮必须有 `aria-label`。**

## 7. 组件约定

- **面板**用 `.panel`（surface-1 + 1px 描边 + 圆角 6px），标题用 `.panel-title`。
- **分段控件**用于一个维度的多个取值（粒度切换），不用四个独立按钮 ——
  它们不是四个操作。选中态用中性亮色。

### 时间线

真实的采集结果是**一天上百个 1–3 分钟的短段**，不是十几块整段。按这个前提定的：

- **轨道必须可见。** 轨道用 `surface-2` + 描边 + 圆角 6px，与面板区分开。
  之前轨道底色 = 面板底色，浅色下三者是同一个白 —— 于是「这段没活动」和
  「这里什么都没画」读起来一模一样，整条时间线没有边框可依。
- **最短段宽 2.5 单位**（铺满时约 3px）。1 单位（≈1.2px）在两个主题里都只是发丝线，
  读起来像渲染噪点而不是数据。代价是最短那批被画得比实际宽 ——
  **与其看不见，宁可略失真**。
- **相邻段之间留 1.5 单位轨道色缝**，让边界能读出来。碎片多的时候 2 单位太宽，
  会把一段连续活动切成条。
- **刻度尺在轨道下方**，不压数据：每 10 分钟一根 4 单位小刻度，每 60 分钟一根
  8 单位大刻度，底端对齐，整条尺高 8 单位（约 9px）。用 `<line>` 画在同一个 SVG 里，
  不为装饰铺 144 个 DOM 节点。
  它是**提示**，不是数据 —— 高度压到不能再小，一高就变成和数据抢戏的装饰品。
  （曾经试过 22% 透明竖线**穿过**整个色块区，碎片一多就成了噪声，读时间反而要眯眼。）
- **「此刻」游标**用独立的 `--color-cursor-now`（`#e63946`，深轨道 3.83:1 / 浅轨道 3.82:1，
  两边几乎对称，所以只有一份声明）。**不复用 `state-critical`** —— 那是错误色，
  借来会让「当前时刻」读成「出错了」。
  - 只画一条线，**不加顶部三角**：三角会盖住第一行色块。
  - **贯穿轨道 + 刻度尺**（`y2` 到 SVG 底），只画轨道那一半就等于没有时间感。
  - **`pointer-events="none"`**：游标横穿整条轨道，绝不能吃掉用户点色块的机会。
  - **鼠标移进容器时降到 40%**（`group-hover`）。再暗就等于没有这个参考点了。
  - **只在看今天时画。** 历史日期上没有"现在"，画了是错的。
- **段内直标的覆盖层只盖轨道那 64px**（`absolute top-0 h-16`），不是整个容器 ——
  容器底下还有刻度尺，直接 `top-1/2` 会把标签推到轨道底边去蹭刻度。
- **命中区大于图元**：未选中的段挂 8px 透明描边，把命中区撑开。描边透明所以不改变观感。
- **所有文字走 HTML 覆盖层，不放进 SVG。** 时间线用 `preserveAspectRatio="none"`，
  放进去的 `<text>` 会跟着横向变形。
- **圆角裁剪和浮层要分开。** 轨道容器 `overflow-hidden` 做圆角，**提示框因此不能放在里面**
  —— 它浮在轨道**上方**，会被裁掉一半。所以外面再包一层只负责定位、不裁剪的 `relative`。
- **刻度尺、游标、网格一律不用 `<rect>`** —— 测试拿 rect 数量断言段数。

### 通用

- **空状态给提示，不留空白**：空时间线、空标题、读取中、读取失败各有各的文案。
- **语义色各占各的 token。** 游标红 ≠ 错误红：`--color-cursor-now` 和
  `--color-state-critical` 即便当下取值接近也不要合并 —— 合并之后
  「当前时刻」就会被读成「出错了」。

## 8. 已知边界

- **同类目内的两个类别区分度有限。** 这是 §2.1 的算术结论，不是没调好。
  放宽的办法是砍类别数（把 8 类合并成 4 类），不是调色。
- **启动时可能有一次主题闪烁。** 系统是浅色而上次选了深色（或反过来）时，
  React 挂载前那一瞬用的是 `@theme` 默认的深色。原因见 §3.1（生产 CSP 不许内联脚本）。
  肉眼几乎察觉不到，但确实存在。
- **固定窗口 1200×700**，未做多分辨率适配（STATUS §4.2 记着这条）。
  布局在窄窗口下会退化到单列，不算坏但也没专门设计过。
- **无高对比度主题。** `forced-colors` 与打印场景没有专门处理。
- **极窄段（< 46 单位）没有段内直标**，只有悬停与图例两条通道。

## 9. 改色板之前

```bash
pnpm build                                              # 产物 CSS 变了才算生效
node design-system/time-scope/verify-palette.mjs        # 必须 exit 0
pnpm vitest run src/preview.test.tsx                    # 整页，两个主题
pnpm vitest run src/preview-timeline.test.tsx           # 时间线专项，碎片化数据
```

`verify-palette.mjs` 从 `src/styles/theme.css` 读色值，不在本仓库里硬编码 ——
所以它校验的永远是真正在用的那套色。它会跑 8 组检查：两份浅色副本是否同步、
两个主题各自的 all-pairs / ordinal / 色块对比度 / 文字对比度 / 状态色 / 直标配字。

`DATAVIZ_SKILL_DIR` 没设时脚本会明确报错而不是悄悄跳过：校验逻辑来自 dataviz skill
分发的 `validate_palette.js`，那份脚本不在本仓库里（脚本会自己在常见位置搜）。

想看效果 —— 两个主题各截一张：

```bash
shot () {  # $1 = html 前缀  $2 = 宽  $3 = 高
  for t in dark light; do

      --virtual-time-budget=3000 file:///$PWD/.preview/$1-$t.html
  done
}
shot preview 1200 700        # 整页
shot timeline 1200 140       # 时间线专项（一天 125 个碎片段）
```
