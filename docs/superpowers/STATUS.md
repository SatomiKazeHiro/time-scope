## 1. ⛔ 先读这一节：看起来像 bug、但是故意的

**下面每一条都有人栽过并花时间改回来。动手前先读完，对不上就别动。**

**这一节的边界**：只记**「别改什么，改了会出什么事」**。
「为什么这样设计」的推导过程（色板怎么搜出来的、判据是什么）住在

### 4.2 引擎的时间边界（2026-10-13 新增）

「凭空造时间」和「重叠段」这两个问题查了 5 轮才定位，**根因是同一个**：
段的 `start_at` / `end_at` 在 `segmenter.rs` 里有 **6 处独立地写**，
每处自己决定往哪边取 min/max。代码里早就写着「不可凭空造时间」，
但守卫只加在 `close_current` 一处 —— 所以同一类问题反复以不同面貌出现。

**现在的收敛状态**：

| 路径 | 状态 |
|---|---|
| `extend` / `close_current` / `absorb` | 全部走 `advance_end`（唯一允许往后推边界的入口，带空档守卫） |
| `fold_short_segments` 的 open 分支 | 已加**相邻检查**（它就是重叠的唯一来源） |
| `merge_into` | 合并语义，保留 min/max；防的是「扩大后越过邻居」 |

**验证（真实数据重放，2026-10-13）**：

```
day          重叠(旧→新)   总时长(旧→新)
2026-10-02     6 → 0      14.73h → 11.46h
2026-10-03     6 → 0      12.06h →  5.85h
2026-10-05    17 → 0      19.77h →  8.67h
2026-10-06     5 → 0      21.05h → 10.26h
2026-10-12     2 → 0      24.00h →  5.69h
合计          84 → 0     160.22h → 106.91h（-53.31h）
```

**关键校验：那 53 小时是真活动还是凭空造的？**
数「有多少 window_focus / title_change 事件落在所有段之外」——
落在段外就说明「本该记为活动却没记」：
```
2026-10-05  活动事件 11554 条，落在段外 0 条
2026-10-06  活动事件  7439 条，落在段外 0 条
2026-10-12  活动事件  6194 条，落在段外 0 条
```
**零丢失** —— 降幅 100% 来自「不再凭空造时间」，不是「把真实活动误删了」。

**注意**：库里的历史段**尚未重放**（84 处重叠还在表里）。读侧兜底让数字正确，
日志会报出藏了多少。真要清干净需逐天重放，见 §4.5。

**踩过的坑，留给下一个人**：
- 合成数据复现不出真实重叠（试到 20000 个事件仍绿）。**用配置参数扫描代替读代码推断**：
  `min_segment_duration_s=0` 关掉合并、`grace_period_s=0` 关掉 absorb，一扫就分开了两条路径
- 逐个把可疑的写边界改成 no-op 重跑真实数据，才找出是 open 分支（`merge_into` 改了重叠数不变）
- 「合成用例能变红」≠「修对了」—— 有三条假设都能写出变红的测试，真实数据重叠数一点没降

### 4.3 设置页（2026-10-08 新增）

设置页从空壳变成两件事。**它回答的是「你的配置缺了什么」**，
与汇总面板的「今天干了什么」是两件事 —— 同一张未覆盖列表曾在当日汇总里
做过并被撤回（用户：那张表答的是配置问题，与汇总面板的时间去向是两回事）。

**规则覆盖**：`get_uncovered_programs` 列出最近 30 天落进 `unknown` 的程序，
按时长降序。点「归类…」选一个类别 → `add_rule` 写回 `rules.toml` 并热替换。
加成功的那个从列表里消失，是这个功能唯一的反馈回路。

占比的**分母是未覆盖总时长，不是全天**：用户要回答的是「我漏配的时间里
有多少给了它」。用全天当分母的话每行都是个位数百分比，
「32% 未分类」的大头就消失在了分母里。

**行为参数**：7 个字段。要重启的四项在控件旁标角标、保存后弹提示 ——
这是本文第 1 节第 16 条「读数就该长得像读数」的延伸，那条讲读数，
这里讲控件：一个当下不起作用的滑块就该说自己不起作用。

**「哪些字段要重启」由后端返回**（`set_config` → `needs_restart`），
前端不复制那张表。依据是参数绑在哪，复制一份就多一处会跟实现对不上的地方，
而那种对不上表现为「界面说不用重启、实际要重启」，最难查。

#### 写回的三条安全性质（都有测试）

1. **坏文件绝不覆盖** —— `rules.toml` 语法错就拒绝写入、磁盘一个字节不动，
   与 `load_rules` 既定的「坏文件只读不写」一致
2. **校验失败发生在写盘之前** —— 空进程名、带路径的、未知类别、
   `idle`/`unknown`（那不是「程序属于哪类」，是「没在用」和「没认出来」，
   写成规则只会造出永远命中不了的死规则）全部在写之前挡下
3. **同名规则明确拒绝而不是追加第二条** —— 引擎按文件顺序取第一个命中的，
   追加会让用户刚选的类别永远不生效，而界面会说「已保存」。那种静默失败比报错难查得多

**修改已有规则仍要手工编辑 `rules.toml`** —— 追加式的写法无法在不重排全文、
不丢注释的前提下替换一条（中间那条块属于谁是有歧义的）。
界面遇到同名规则会明确报错并说清去哪改，不假装成功。

### 4.4 已知限制（决定不做）

| 事项 | 性质 |
|---|---|
| 同层级内两个类别区分度有限 | 色觉安全的算术后果（§1 第 3 条）。放宽只能砍类别数，不是调色 |
| 细短段（1–3 分钟）鼠标命中区只有 2–3px | 靠 8px 透明描边扩；已能用方向键精确走到。**用户 2026-10-06 决定先放一放** |
| 详情卡片的前后段导航不跨天 | 前端只持有当天段，跨天要么加缓存要么按需发 IPC，还要跟轮询对齐失效 |
| 强杀丢最后几秒 Event | spec §8.1 明确接受。正常退出已 flush，只有崩溃会丢 |
| 固定窗口 1200×700 | 无多分辨率适配。时间线用 viewBox，缩放不会算坏 |
| 启动时可能闪一下主题 | 系统浅色而上次选深色时。生产 CSP 不许内联脚本（§1 第 5 条） |
| 热力图 371 个 Tab 停靠点 | 每格约 13px，鼠标点得准，收益几乎全在无障碍。**用户 2026-10-06 决定先放一放** |
| 归类用固定 offset，DST 日差一小时 | 跟随全项目既有假设（§1 第 21 条） |
| **合盖/唤醒不被记录** | `PowerRegisterSuspendResumeNotification` 在本机返回 `HRESULT(0x80070057)`（E_INVALIDARG），实测注册不上。**锁屏/解锁不受影响**（走 `WTSRegisterSessionNotification`，2026-10-13 真机验证：事件正常落库）。影响面小 —— 合盖通常会触发系统自动锁屏，那时走的是锁屏那一路。**决定先记为已知限制**，要修得先查 MSDN 并试别的注册方式 |

## 5. 关键决策（只留不在「别动这里」里的）

| 决策 | 原因 | 代价 |
|---|---|---|
| engine 零 IO、零 Tauri | 可重放的前提 | 边界靠测试守 |
| collector 用第二条 channel 转发 Event | collector 不认识 engine | consumer 多一个参数 |
| `ActivityContext` 沿用而非重建 | 否则心跳冲掉 application，每心跳切一段 | 无 |
| grace 吸收要「复活前一段」 | 「不切段」会留下错误 context | 需要 `previous_application` |
| 落库门槛 `max(min, grace)` | 吸收只能复活未落库的段 | 修了 spec 默认值 30<60 的隐患 |
| 短段找不到长邻居就压着 | 宁可不并，不可跨时间并错 | 孤立方段延迟最多 3 倍门槛 |
| `SharedConn = Arc<Mutex<Connection>>` | `Connection` 是 `Send` 非 `Sync` | 每次读写多一次锁 |
| `idle_seconds` 用 u32 + `wrapping_sub` | `dwTime` 是 u32，49.7 天回绕 | 用 u64 会「永不 idle」 |
| `payload` 只存 `EventType` JSON | id/timestamp/type 各有独立列 | 存全量会有两个真相来源 |
| evidence 用软引用 | 段先于 Event 落库 | 失去引用完整性 |
| 重放「删当天 + 写当天」合成单事务 | 否则失败后那天永久空白 | `claim` 必须在成功之后 |
| `classifier_version` 由**内容**派生 | 只由条数派生时改规则版本号不变 | 不能用 SipHash，版本号会落库 |
| 汇总页三个 IPC 按数据成本分层 | 七个指标里六个走 `activities`（毫秒级），只有标题排名走 `events` | 最贵的那条恰好是懒加载的 |
| 热力图固定 53 周不随选中变 | 它是导航图，不是被导航的对象 | 见 §1 第 18 条 |
| 窗口标题在 Rust 侧归一化 | 放前端会让同一归一化值散成多行，合并不了 | — |
| 不引入图表库 | 圆环是 4 个 `<circle>` + `stroke-dasharray` | 当时产物 +14 KB，没有 d3 的 540 KB。（当前值见 README「启动慢」一节；此处 276 KiB ≈ 283 KB 是同一个文件） |
