## 准备

```bash
pnpm install
pnpm tauri dev
```

首次运行生成 `%APPDATA%/time-scope/` 下的 `config.toml`、`rules.toml` 与
`time-scope.db`。想从干净状态观察（**会删掉全部历史数据**）：

```bash
rm -rf "$APPDATA/time-scope"
```

> ⚠️ 验证采集时**务必切到时迹之外的窗口**。`WINEVENT_SKIPOWNPROCESS`
> 会过滤本进程自己的窗口，切到自己不会产生 focus 事件。

**日期切换**（两页都有这套控件）：

- [ ] 「← 前一天」显示昨天；「后一天」能回到今天

- [ ] 跨零点的段只归属一天（这条曾出过 bug：按 `start_at` 归属会让它第二天整天消失）

## I. 锁屏与睡眠（风险最高的部分）

- [ ] 锁屏后等 1 分钟再解锁：时间线出现一段 **idle**，**没有 active 段**，且 idle 覆盖锁屏那段
- [ ] 锁屏前的工作段在锁屏时刻**收尾**，不延伸到锁屏之后
- [ ] 锁屏期间有输入心跳（键盘/鼠标活动）也不产生 work 段
- [ ] 合盖午休 30 分钟后开盖：出现一段 idle（结束时间会**晚于**实际开盖，这是已知限制，spec §12）
- [ ] 锁屏 8 小时后查看：那一段是 idle，不是 8 小时 work
- [ ] 锁屏期间不强杀进程：解锁后应用恢复正常采集
- [ ] **挂机 2 小时后看专注度不是 100%** —— 空闲不计入专注度分母
      （前端已有回归测试 `src/lib/metrics.test.ts` 的 `focus ignores idle time entirely`）

## J. 配置与规则容错

- [ ] 改 `config.toml` 的 `idle_threshold_s = 10` → 重启 → 停手 15 秒就出现 idle
- [ ] `idle_threshold_s = 0` → 重启 → 仍能启动（被夹到 10），不崩、不产生海量段
- [ ] 把 `config.toml` 写成乱字符 → 重启仍正常（用默认值），**且文件内容没被覆盖**
- [ ] 只写错一个字段（如 `idle_threshold_s = "soon"`）→ 其余字段照常生效
- [ ] 删掉 `config.toml` → 重启 → 自动重新生成默认模板
- [ ] 把 `heartbeat_every_s` 改小（如 2）→ 重启 → 段的数量明显变多（确认参数真的接上了）
- [ ] 把 `rules.toml` 改成一堆乱字符 → 重启应用**正常启动**，终端打印「规则文件不可用」，时间线仍有颜色
- [ ] 改坏后的 `rules.toml` 内容**没被覆盖**（还是你写的那堆乱字符）

## 自动化已覆盖、不必人工重复

- 规则文件首次生成与容错解析（`rules` 模块单测）
- 进程名大小写、路径只比文件名（`classifier` 单测）
- 短段合并与幽灵段防护（`segmenter` 单测）
- 全量重放幂等：同一批 Event 重放两次产生相同段数，不累积重复
- engine 零 IO 零 Tauri 边界（`crates/engine/tests/boundaries.rs`）
- 降级路径：托盘构建失败时关窗仍能退出（`a_failing_tray_must_not_leave_the_app_unclosable`）；
  会话通知注册失败时 stderr 有提示且应用照常启动
  （`a_failed_registration_degrades_instead_of_panicking`）

## 已知限制（不必验，验了也会这样）

- 归类按固定时区偏移（UTC+8）计算「一天」，**DST 地区会差一小时**（STATUS §1 第 21 条）
- 固定窗口 1200×700，无多分辨率适配
- 详情卡片的前后段导航**不跨天**
- 原始事件保留 365 天，`activities` 永久保留
