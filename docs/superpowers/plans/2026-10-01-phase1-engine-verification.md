## 人工步骤

### 0. 前置

```bash
node --version && pnpm --version && rustc --version
cargo test --manifest-path src-tauri/Cargo.toml --workspace   # 151 passed
pnpm test                                                      # 57 passed
pnpm build
```

> ⚠️ `cargo test` **必须带 `--workspace`**。`src-tauri/Cargo.toml` 同时是 workspace 根和应用包，
> 不带的话只跑根包并显示绿色。

清空旧数据（可选，保证观察干净）：

```bash
rm -rf "$APPDATA/time-scope"
```

### 1. 启动

```bash
pnpm tauri dev
```

- [ ] 窗口打开，标题 "Time Scope"
- [ ] 看到**粒度切换器**（10分 / 30分 / 60分 / 120分，30分默认高亮）
- [ ] 看到 24h 时间线
- [ ] 库为空时显示"这一天还没有活动段"
- [ ] 终端打印两行：已生成/已加载规则、db 路径

### 2. 分类着色（**本步是第二步的核心，人工确认价值最高**）

- [ ] 切到 **VS Code** 停 10 秒 → 时间线出现**蓝色**块
- [ ] 切到 **浏览器** 停 10 秒 → 出现**橙色**块（browsing）
- [ ] 切到 **微信/QQ** 停 10 秒 → 出现**青色**块（communication）
- [ ] 切到**规则里没有的程序**（比如 Clash）→ 出现**浅灰**块（unknown）
- [ ] 时间线上同时能看到 ≥3 种颜色
- [ ] 点击任意色块 → 详情显示：类别、起止时间与时长、应用、置信度、`规则 rules:15`、证据条数

> 改规则即时验证：编辑 `%APPDATA%/time-scope/rules.toml`，把某程序加一条规则，
> **重启应用**后看它的颜色是否按新规则变了。改坏语法后重启应仍能用（退回默认）。

### 3. 粒度切换

- [ ] 依次点 10分 / 30分 / 60分 / 120分，按钮高亮跟随
- [ ] 每切一次**不重新查后端**（顶部"N 段 · M 桶"里的 M 变，N 不变）
- [ ] 10 分时桶最多、120 分时桶最少
- [ ] 任何粒度下段的总数 N 都不变

### 4. 当日汇总

- [ ] 页面下方出现"当日汇总"区块
- [ ] 每个 category 一行：名称 + 比例条 + 时长
- [ ] 时长之和 ≈ 各段时长之和
- [ ] 空闲时会多出灰色 `idle` 行

### 5. 日期切换

- [ ] "← 前一天"：显示空态（昨天没数据）或昨天的时间线
- [ ] 回到今天，今天的数据仍在
- [ ] 非今天时出现"回到今天"按钮

### 6. 跨天与重放

- [ ] 关闭应用 → 把系统日期往后调一天（或等跨零点）→ 重启
- [ ] 昨天的段仍在（"← 前一天"能看到）
- [ ] 今天的段从今天重新开始，不与昨天重叠
- [ ] 切到昨天时**每段起止时间都落在昨天**（本地时区半开区间）

### 7. 规则改坏容错

- [ ] 把 `rules.toml` 改成一堆乱字符 → 重启应用
- [ ] 应用**正常启动**，时间线仍有颜色
- [ ] 终端打印"规则文件不可用/解析失败"
- [ ] `rules.toml` 内容**没被覆盖**（还是你写的那堆乱字符）

### 8. 常驻开销

- [ ] 开着应用放置 5 分钟，任务管理器观察 CPU ≈ 0%
- [ ] 内存占用 < 80 MB（spec §12 的预算）

## 已知限制

- 空闲阈值 300 秒（spec §5.3），验证灰色 idle 块要停 5 分钟以上
- `WINEVENT_SKIPOWNPROCESS` 会过滤本进程自己的窗口，验证 focus 要切到 Time Scope 之外
- 手工查库需把 `time-scope.db`、`-wal`、`-shm` 三个文件一起复制出来再打开
