## 最终口径（2026-10-13 当天拍板并做完）

**笼统，不做细分。** 用户原话：「既然干不了，为什么不后退？直接笼统解决，
而细分是未来的方向，现在就是要明确的笼统，明确的将一类事务聚在一起
形成一个模糊但边界清晰的个体。」

```
focus = 主导类别时长 / 桶内有输入的时长
```

规则只有一条：**没在动的时间不进分母。**
- 人不在（锁屏 / 长时间无输入）→ 摘出去，不会显示成满档
- 全程在动 → 100%
- 「边做边走神」与「看视频」**当前同分** —— 这是有意的，不是遗漏

为什么这样够用：读者能反推某个格子为什么是这个颜色。
一个说不清口径的复合公式（「专注度 × 占用率」之类）比粗糙的公式更没用。

## 为什么心跳必须带窗口起点

`heartbeat.active_seconds` 说的是「**过去 10 秒**里有几秒在动」，
**不说那几秒在哪**。段只覆盖其中一部分，缺了窗口起点就算不出
「**段内**有多少时间在动」。

实测过的三种上限写法：
```
第 1 版  min(end_at - start_at)  → 心跳到达时 extend 还没跑，
                                     end_at == start_at，第一笔整笔丢
第 2 版  min(ts - start_at)      → 段刚开时这个值也很小，窗口前半段
                                     （落在段外）被一起丢掉
现在     窗口 ∩ 段 的重叠        → 对的
```
**每笔夹住还不够，总量也要夹**：窗口之间会重叠（两个心跳可能报同一段时间），
累加起来能超过段有多长 —— 实测四个 10 秒窗口累出 35 秒而段只有 20 秒。

## 三个边界（`null` 与 `0` 必须分开）

| 情况 | `inputMs` | 行为 |
|---|---|---|
| 这一桶确实没动 | `0` | focus = 0，时间线**不涂色** |
| 2026-13 之前的历史数据 | `null` | **退回旧口径**（分母用 `activeMs`），照常涂色 |
| 有输入 | 数字 | 正常算 |

`null` 与 `0` 混成同一个 0 会让历史日期看起来像「那段时间完全没人用电脑」。
