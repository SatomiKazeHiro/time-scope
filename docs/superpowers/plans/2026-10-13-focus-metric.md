## 前端：没做，因为口径有个未决的缺口

### 用户最初要解决的
「专注度 100%」—— 单类别桶导致 `主导类别/非idle时长` 恒等于 1。
实测全库 185 个满档桶里 **148 个（80%）是单类别桶**，构造性的 100%。

### 用户 2026-10-13 拍板的口径
```
focus = 主导类别时长 / 有输入时长
```
理由：实测看视频时长浏览段里，心跳报 0 的比例 14%–74%，
**但从不连续 300 秒** —— 人是间歇性动手的。所以这个量能区分
「人不在」（锁屏/连续无输入）与「人在但不专注」（看视频）。

### ⚠️ 停在这里的原因：口径有真实缺口

`focus = 主导类别 / 有输入时长` **在单段情况下退化**：

| 场景 | 主导 | 有输入 | 该公式 | |
|---|---|---|---|---|
| 认真写代码 60 分 | work | 60 分 | 100% | ✅ |
| 一件事做 60 分、走神 40 分 | work | 20 分 | **100%** | ❌ 40 分没动 |
| 看视频 60 分、间歇动手 20 分 | browsing | 20 分 | **100%** | ❓ |

**分母变小不会让占比变小**，夹到 1 之后还是 100%。所以这个口径
解决了「人不在 vs 人在」，**没解决「一直在做但不专注」**，
而且让「看视频」和「摸鱼」画得一模一样。

### 三条路（用户 2026-10-13 选择 **C：先停**）

**A（我推荐过，用户未采纳）** —— 乘占用率：
```
focus = 主导类别占比 × (有输入时长 / 段总时长)
```
认真写 60/60 → 1.0×1 = 100% ✅
边做边走神 → 1.0×0.33 = 33% ✅
看视频 → 1.0×0.33 = 33%（与摸鱼同分，如实反映「都是被动」）
代价：公式复杂，图例要重新解释。

**B** —— 只按「有输入时长」相对全天判高低，不做占比。
仍解决不了「做但不专注」，但已解决最初的问题。

**C** —— 停。前端不做，等口径定了再说。

### 已经踩过的坑（写实现时注意）
- 累加上限别写成 `end_at - start_at`：心跳到达时 `extend` 还没跑，
  `end_at` 仍等于 `start_at`，整笔会被丢掉。要用 `ts - start_at`。
- 测试辅助函数 `seg()` 默认 `activeMs = 段跨度`，不然所有 fixture
  都变成「历史数据」，`inputMs` 全是 null，测试会莫名其妙地全绿。
